### 目的
「バトルファクトリーのバトルエンジンから実装を開始」という依頼を受け、CLAUDE.md の「やること」B（対戦エンジン側の準備：フェーズ1・2で Agent を繋ぐのに必要なもの）の5項目を進める。対戦エンジン自体（フェーズ0）はほぼ完成済みのため、Agent から判断を差し込めるようにし、同じシードで同じ対戦を再現できるようにすることを目的とした。

### 実施内容
- **乱数の差し替え**：`Battle(side1, side2, rng=None)` を追加し、`battle.py` 内の `random.*` をすべて `self.rng.*` に置き換えた。`check_hit`・`roll_critical`・`calculate_damage`・`calculate_confusion_damage` に `rng` 引数（省略時は `random` モジュール）を足し、持ち物（せんせいのツメ・きあいのハチマキ）・特性（メロメロボディ・接触で状態異常にする特性）・技の追加効果・`random_switch_policy` は `battle.rng` を使うようにした。せんせいのツメのため `BaseItem.try_move_first` の引数に `battle` を追加した。
  - 省略時は今まで通り `random` モジュールを使うので、既存テストの `monkeypatch`（`battle_module.random.random` 等）はそのまま動く。ただし `ability/shared.py` から `import random` を消したため、`test_group1_effects.py` の1テストのパッチ先を `"ability.shared.random.random"` から `"random.random"` に変えた。
- **技選択のポリシー**：`Trainer.move_policy`（`(battle, trainer, 選べる技のリスト) -> 技`）を追加。`select_move` の固定・制限処理はそのまま残し、最後の「選べる技からどれを選ぶか」だけをポリシーに聞く。`None` ならランダム。リスト外の技を返したら `ValueError`。
- **交代先のポリシー**：`Trainer.replacement_policy`（`(battle, trainer, 候補, 理由) -> インデックス`、理由は `"faint"`/`"u_turn"`/`"baton_pass"`）と `Battle.choose_replacement` を追加。`resolve_faints`・とんぼがえり・バトンタッチがこれを使う。`None` なら今まで通り手持ち順で最初の生存個体。
  - `resolve_faints` は、両者が同時に瀕死になったとき相手の交代先を見ずに選べるよう、「両者が選ぶ→両者が交代する」を繰り返す形に作り直した（以前はトレーナー1が交代し終えてからトレーナー2の処理だった）。
- **引き分け**：`Battle.get_winning_trainer(draw_winner=None)` を追加。同時全滅なら `draw_winner` を返すので、ファクトリー側で相手を渡せば仕様書10節どおりプレイヤーの負けにできる。あわせて `Battle.get_side` を追加。既存の `get_winner()` は残した。
- **イベントの記録**：`src/battlelogic/events.py` に `BattleEvent(turn, kind, side, data)` を新設し、`Battle.events` に積むようにした。種類は `switch_in`・`turn_start`・`move`・`move_result`・`cant_move`・`hp`・`faint`・`status`・`item`・`battle_end`。
  - HP・状態異常・持ち物の変化は書き換える箇所が多い（HP だけで16か所）ため、変える側に手を入れず、行動・交代・ターン終了時の各段階で手持ち全員のスナップショットの差分を取って作る方式にした（何によって変わったかの原因は持たない）。
  - `Battle(..., record_events=False)` で記録を止められる。300戦で計測すると記録あり0.69秒・なし0.49秒だった。
- テスト `tests/test_engine_hooks.py`（53件）を追加：同じシードで経過まで一致すること（20シード）、シードが違えば結果が変わること、各ポリシーの呼ばれ方と不正な値での `ValueError`、同時瀕死で相手の交代先が見えないこと、とんぼがえり・バトンタッチの交代先、引き分けの扱い、HP イベントが途切れず最終 HP と一致すること・瀕死の数が合うこと、`move`/`move_result` が対になること、記録を止められること。
  - 最初はテストに「かたくなる」を使ったが技データに無く失敗したので、「てっぺき」に変えた。
- `src/main.py` の結果を変更前後で比べ、分布がほぼ同じ（変更前：リザードン6135・引き分け1787・メガニウム2078、変更後：6118・1889・1993）であることを確認した。「引き分け」が多いのは1000ターンの上限に達する対戦で、変更前からある挙動。
- README の「実装状況」に「Agentを繋ぐための口について」の節を足し、「一部だけ実装しているもの」から交代先の項目を消し、やることリストを更新した。CLAUDE.md の「やること」B を ✅ にした。
