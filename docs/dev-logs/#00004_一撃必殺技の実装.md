### 目的
これまで「未実装」としていた一撃必殺技（じわれ・ぜったいれいど・つのドリル・ハサミギロチン）を実装する

### 実施内容
- ユーザーから一撃必殺技に対応する技名を聞かれ、README/コード上でメモしていた4技（じわれ id88、ぜったいれいど id166、つのドリル id167、ハサミギロチン id229）を回答
- 実装方針は`high_crit`と同じパターン（`BaseMove`にデフォルト属性を持たせ、該当技だけサブクラスでTrueに上書き）を踏襲
- `move/base_move.py`の`BaseMove.__init__`に`self.is_ohko = False`を追加
- 該当4技の`move_XXX.py`から「一撃必殺技は未実装」というコメントを削除し、`self.is_ohko = True`を追加
- `battlelogic/damage.py`の`calculate_damage`に一撃必殺技用の分岐を追加：タイプ相性が0倍（無効）なら失敗（0ダメージ）、そうでなければ`defender.current_status.current_hp`と同じ量のダメージを返す（＝命中すれば必ず瀕死にする、通常のダメージ計算式・STAB・乱数は無視）
- 動作確認の過程で、`Struggle`（わるあがき）クラスが`BaseMove.__init__`を経由せず自前で属性を設定している設計だったため、後から追加した`is_ohko`属性を持っておらず`AttributeError`が発生することが判明
  - 300試合のランダムテストで2件エラーが発生し原因を特定
  - `move/struggle.py`に`self.high_crit = False`・`self.is_ohko = False`を追加して解消
- 修正後、じわれをひこうタイプ（無効）とくさタイプ（通常）の両方に対して`calculate_damage`で直接検証し、無効時は0、通常時は相手の残りHPと同値のダメージになることを確認
- `Battle.use_move`経由でも同様に動作することを確認
- `main.py`の1万戦シミュレーション、500試合のランダム種族・技構成テストをエラー無しで完走することを確認
