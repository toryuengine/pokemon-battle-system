### 目的
README の「一部だけ実装しているもの」にあった、状態異常を防ぐ特性（めんえき・ふみん・やるき・マイペース・みずのベール・どんかん）が「かからないようにするだけで、すでにかかっている状態異常を治さない」問題を直す。トレース・ものまね（このコードでは変身の技）で特性を得たとき、かたやぶりの相手に状態異常にされたときなどに、すぐ治るようにする。

### 実施内容
- `BaseAbility` に `on_update(battle, pokemon)` フックを追加した。状態が変わった後（行動・交代・ターン終了時の各処理の後）に呼ばれる
- `Battle.activate_held_items_on_field` から、持ち物の発動の直前に `activate_update_ability` を呼ぶようにした。持ち物がもともと発動するタイミングをそのまま使っている。特性を先に判定するので、めんえきで治るどくにラムのみを使ってしまうことは無い。瀕死の個体と、いえきで特性を消された個体では発動しない
- `StatusImmunityAbility.on_update`：防ぐ状態異常にかかっていれば `cure_status` で治す（マイペースはこんらんの残りターンを0にする）。治したら `reveal_ability` で特性が判明したことを記録する
- どんかん（`ability_012.py`）の `on_update`：メロメロ状態なら解除し、特性が判明したことを記録する
- トレースは交代時の `switch_in`、変身は `execute_move_action` の最後、対戦開始時・瀕死の交代時はそれぞれの処理の後に `activate_held_items_on_field` が呼ばれるので、どの場合も回復が起きることを確かめた
- `tests/test_status_cure_abilities.py` を追加した（13件）。テストした内容：6特性の回復、防ぐものと違う状態異常は治さないこと、もうどくの回復、いえきの間は治らないこと、トレースでめんえきを得たときの回復、変身でふみんを得たときの回復、かたやぶりのどくどくの直後の回復、ラムのみより先に治ること
- 変更前のコードで新しいテストを走らせ、11件が失敗することを確かめた（残りの2件は、治さない側の確認なので変更前でも通る）
- README：「一部だけ実装しているもの」から該当項目を削除した。特性の一覧と「特性・持ち物の発動」に回復の説明を足した。治すタイミング（持ち物と同じ段階で、持ち物より先）は「推測で決めた細かい仕様」に書いた
- 環境に pytest が無かったので pip で入れた
