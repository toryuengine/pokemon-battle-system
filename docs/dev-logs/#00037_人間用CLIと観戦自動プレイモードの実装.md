### 目的
フェーズ2として、人間がバトルファクトリーを遊べるCLIと、AIに自動で進めさせるモードを作る。2つを別々の仕組みにせず、同じ `FactoryChallenge` の上で判断する Agent だけを差し替える形にする（CLAUDE.md 3.2・4節）。

### 実施内容
- 観測に「見える出来事」を追加した（`factory/observation.py`・`factory/battle_runner.py`）
  - `VisibleEvent`：`Battle.events` から、相手のセットの番号（indivisual_id）と相手に与えたダメージの実数を除き、相手のHPを割合にしたもの
  - `TurnObservation.new_events`：前回の観測から今までの出来事。人間に「前のターンに何が起きたか」を見せるために必要だった
  - `BattleEndObservation` と `FactoryAgent.on_battle_end`（デフォルトは何もしない）：最後のターンの経過と勝敗を Agent に渡す。factory は agents を import しないので getattr で呼ぶ
- `FactoryChallenge.play_next(on_battle_end=)` を追加し、`play_challenge` はこれを繰り返す形にした。負けたときの連勝のリセットは `play_next` の中で行う
  - 最初は CLI で勝敗のまとめを `play_next` の後に出していたが、交換の入力の後にまとめが出てしまったので、対戦直後（交換の前）に呼ぶ関数を渡せるようにした
- Agent の一覧を `experiments/evaluate.py` から `agents/registry.py` に移し、評価とCLIで同じ名前で選べるようにした
- `src/interface/` を新設
  - `text.py`：IDから名前を引き、ポケモン・ヒント・場の状況・行動を文字列にする（print はしない）
  - `narrator.py`：見える出来事を本編風のメッセージにする。変化技は hit が立たないことがあるので「外れた」とは言わない
  - `human_agent.py`：`HumanAgent`。入力と出力は関数で差し替えられる。`q` でやめる・`d` で手持ちの詳細。`advisor` に別の Agent を渡すと、その選択を助言として表示する
  - `spectator.py`：`SpectatorAgent`。AIの判断をそのまま使い、経過と選んだ行動を表示する
  - `cli.py`：`play`（人間）・`watch`（観戦。`--pause` で1ターンずつ）・`auto`（`experiments.evaluate` と同じ自動プレイ）
- `tests/test_interface.py` を追加した（49件）：出来事が漏れも重なりもなく届くこと、相手の隠れた情報が入らないこと、`play_next` と `play_challenge` が同じ挑戦になること、決まった入力で負けるまで遊べること・同じシードと入力なら同じ挑戦になること、不正な入力の聞き直し、`q` でやめられること、助言の表示、観戦しても自動プレイと同じ挑戦になること、全出来事をメッセージにできること
  - 最初に書いた並び順・交換のテストは `rent()` の後に `play_next()` を呼んでいて、レンタルが2回行われて失敗した。テストを `play_battle()`・`offer_trade()` を使う形に直した
- README（実装状況・やることリスト・「CLIについて」の節・観測と進行の説明）と CLAUDE.md（フェーズ表・やること・実行方法）を更新した

### 結果
- テストは全466件が通った
- `python -m interface.cli watch --seed 3 --max-battles 2` と、入力を流し込んだ `play --seed 5 --advisor random` を実際に動かし、表示を確かめた
- 自動プレイの成績は変更前と同一だった（シード1・2000回：平均連勝数0.534・対戦3069）。ただし見える出来事の変換の分だけ遅くなった（10.3秒 → 11.9秒、約15%）
- 人間が実際に端末で手で遊んだ確認はしていない（入力の流し込みによる確認のみ）
